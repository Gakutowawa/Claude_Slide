# スライド作成フレームワーク（ストーリー構築ルール）

> このファイルは「何を書くか（ストーリー）」のルール。
> 「どう見せるか（デザイン）」は `slide_template.html` 側に分離してある。
> 使い方：STEP 0 の入力欄を埋めて、このファイルごと Claude に渡す。

---

## STEP 0｜源流の定義（ここを埋めてから始める）

| 項目 | 記入欄 |
|---|---|
| ビジネス上の目的 | （例：次年度予算化の意思決定を得る） |
| 意思決定者 | （例：副市長・財政課長） |
| 決めてほしいこと（Ask） | （例：施策Aへの投資可否） |
| 判断基準／相手の関心事 | （例：住民負担削減、職員工数、初期費用） |
| 制約条件 | （例：予算上限、法令、既存システム） |
| 資料の枚数・時間 | （例：本編8枚／20分） |

**原則**：この目的から逆算して「最後のスライドで何を言い切るか」を先に決め、そこから逆順にストーリーを組む。

---

## STEP 1｜空＝事実・現状（SCQA の S）

書くべきもの
- 業界人が共通認識として持っている前提（Situation）
- 客観データによる現状把握（時系列・構造分解・比較の3視点で最低1つずつ）

**示唆を書く場合のルール（重要）**

| 要素 | 内容 |
|---|---|
| 主張（示唆） | 「〜である」という解釈 |
| 根拠 | なぜそう言えるか（複数） |
| 裏付け分析 | その根拠を成立させる具体的な分析・データ |

→ 3点セットが揃わない示唆は「仮説」と明示するか、書かない。

チェック
- [ ] 相手が「知っている」と頷ける内容から入っているか
- [ ] 事実と解釈が視覚的に分離されているか（本文＝事実／メッセージ＝解釈）
- [ ] 数値には必ず出典・期間・定義を注記したか

---

## STEP 2｜雨＝課題（SCQA の C・Q）

手順
1. 現状（空）と目的（STEP 0）の**ギャップ**を定義する
2. ギャップを構造分解し、**なぜギャップが埋まらないのか**の要因を MECE に列挙
3. 要因を「起きている事象」ではなく**構造要因**まで掘る（Why を3回）
4. インパクト × 解決可能性で、取り組むべき課題を絞る

**仮説思考での進め方**
- 先に「課題はこれだろう」という仮説を1文で書く
- その仮説が成り立つ／崩れる条件を書き出す
- 条件を検証できる最小限の分析だけを実施する（網羅的分析はしない）

チェック
- [ ] 課題が「困っている状態」ではなく「解くべき問い（Q）」の形になっているか
- [ ] 課題の粒度が揃っているか
- [ ] 「だから何が問題なのか」が意思決定者の判断基準に接続しているか

---

## STEP 3｜傘＝解決策（SCQA の A）

### 3-1. 施策の発散（ロジックツリー）
- 課題ごとに「What to do」をツリーで展開（第2階層まで、各3〜5個）
- 発散段階では実現性で切らない。ヌケモレのほうが致命的

### 3-2. 比較軸の設定と評価
軸はビジネス目的から導く。標準は以下から3〜5個選ぶ。

| 軸の候補 | 定義の例 |
|---|---|
| 効果（インパクト） | 目的指標への寄与度 |
| 実現可能性 | 体制・技術・法令面での障壁の低さ |
| 初期コスト／ランニング | 投資規模と回収期間 |
| スピード | 効果発現までの期間 |
| 受容性 | 住民・現場職員・関係部署の納得感 |
| 持続性 | 単発でなく仕組みとして残るか |

- 評価は ◎○△× の4段階＋**評価理由を1行**で必ず添える
- 「なぜその評価なのか」の裏付けデータが弱い軸は、軸ごと落とす

### 3-3. 絞り込み → What to do
- 選定した施策と、**落とした施策とその理由**をセットで示す（相手の反論を先に潰す）

### 3-4. How to do（実行への落とし込み）
選定施策ごとに以下を定義する。目的に応じて取捨選択。

| 項目 | 内容 |
|---|---|
| 優先順位 | 効果 × 着手容易性でランク付け |
| アクション手順 | 誰が・何を・どの順で |
| 実行上のポイント | つまずきどころと回避策 |
| スケジュール | フェーズ（検証→試行→展開）とマイルストーン |
| 推進体制 | 責任者・関与部署・外部リソース |
| KPI | 何をもって成功とするか |

チェック
- [ ] 明日から動ける粒度になっているか（「検討する」で終わっていないか）
- [ ] 誰がやるかが書かれているか

## エグゼクティブサマリーの規約

資料冒頭に1枚。**本編を読まなくても意思決定できる**内容にする。

構成（空→雨→傘の順に、本編の主メッセージを圧縮して並べる）
1. 現状認識（空）：2〜3行
2. 課題（雨）：2〜3行
3. 打ち手（傘）：2〜3行
4. 結論／依頼事項（Ask）：1〜2行、最も目立たせる

原則
- **本編の各スライドの主メッセージを1つも欠かさず含める**（過不足のチェックリストとして使う）
- サマリーと本編でメッセージの表現をブレさせない
- 数字を最低1つ入れる

---

## 全スライド共通のレイアウト規約

| 位置 | 要素 | ルール |
|---|---|---|
| 左上 | スライドタイトル | 内容の「ラベル」。体言止め。 |
| 中央上 | 主メッセージ | 大きめ。**1スライド1メッセージ**、40〜60字で言い切る |
| 中央 | ボディ | 主メッセージを証明する図表。図表は主張の根拠であって飾りではない |
| 左下 | 注釈・出典 | 定義、前提、対象期間、出典を明記 |
| 右下 | ページ番号 | 通し番号 |

## 提出前チェックリスト

- [ ] 主メッセージだけを縦に読んで、ストーリーが通るか
- [ ] 空 → 雨 → 傘 の順序が崩れていないか
- [ ] すべての図表が、そのスライドの主メッセージを支えているか
- [ ] すべての示唆に「根拠＋分析」があるか
- [ ] すべての数値に出典があるか
- [ ] 最後に Ask（依頼事項）が明示されているか
