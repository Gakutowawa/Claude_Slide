# スライド作成フレームワーク

BCG公共系の日本語資料を参考にした、空・雨・傘 × SCQA のスライド生成コード。
`index.html` をブラウザで開くだけで動く（ビルド不要・ネット接続不要 ※フォントのみCDN）。
納品は **ブラウザの印刷 → PDFに保存**（用紙：横／余白なし／背景グラフィックON）。

---

## どこを触ればいいか

| やりたいこと | 触るファイル |
|---|---|
| **中身を書き換える** | `data/00〜04-*.js` |
| 色・文字サイズ・余白を変える | `css/01-tokens.css` |
| スライドの版面ルールを変える | `css/02-frame.css` |
| 図表の見た目を変える | `css/04-charts.css` |
| **新しい図表を追加する** | `js/components.js` ＋ `css/04-charts.css` |
| パートの順番を入れ替える | `index.html` の `<script>` の順番 |
| ストーリーの組み立て方を確認する | `docs/story-rules.md` |
| 図表のデータ書式を調べる | `docs/component-guide.md` |

`js/render.js` は組み立て役なので原則そのままでよい。

## ファイル構成

```
index.html                 ← エントリ。読み込み順＝スライド順
css/
  01-tokens.css            色・文字・版面（★最初に触るのはここ）
  02-frame.css             スライド枠：左上タイトル／中央上メッセージ／注釈／ページ番号
  03-blocks.css            カード・リスト・数値・表・ステップ
  04-charts.css            横棒・ウォーターフォール・2軸マップ・ツリー・評価表・ロードマップ
  05-print.css             PDF書き出し、はみ出し警告
js/
  components.js            データ → HTML の変換部品（図表を足すのはここ）
  render.js                スライド枠の組み立て、ページ自動採番、はみ出し検知
data/
  config.js                案件の基本情報（目的・意思決定者・Ask）
  00-front.js              表紙／アジェンダ／エグゼクティブサマリー／検討目的
  01-sora.js               【空】外部環境・利用実態・来庁理由・業務量・他自治体比較
  02-ame.js                【雨】ギャップ・構造分解・Why深掘り・優先順位
  03-kasa.js               【傘】施策展開・評価軸・評価・絞り込み・手順・工程・効果試算
  04-close.js              リスク／依頼事項／Appendix中扉
docs/
  story-rules.md           ストーリー構築ルール（Claudeに渡す用）
  component-guide.md       図表のデータ書式リファレンス
```

現在のサンプルは全26セクション／通し21ページ（表紙・中扉はページ番号を振らない）。

---

## 新しい資料をつくるとき

1. `docs/story-rules.md` の **STEP 0** の表を埋める
2. `data/config.js` に目的・意思決定者・Ask を書く
3. `data/*.js` の中身を差し替える（構成は流用できる）
4. ブラウザで開き、赤枠の警告が出ていないか確認する
5. 印刷 → PDF

Claudeに続きを書かせる場合は、`docs/story-rules.md` と `docs/component-guide.md`
の2つを渡すと、この書式のまま生成できる。

## 守っているルール

- 冒頭にエグゼクティブサマリー。本編の主メッセージを1つ残らず含める
- 各スライドは 左上にタイトル／中央上に主メッセージ（大きめ）／右下にページ番号／左下に注釈・出典
- 1スライド1メッセージ。主メッセージだけを縦に読んでストーリーが通ること
- ストーリーは 空（事実）→ 雨（課題）→ 傘（打ち手）
- 示唆を書くときは「主張＋根拠＋裏付け分析」の3点セット
- 施策評価は比較軸ごとに ◎○△ ＋ 評価の根拠1行
- 数値には必ず出典・定義・期間を注記する
